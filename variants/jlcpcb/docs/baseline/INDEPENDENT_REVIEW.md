# Independent review and verification plan

**Historical baseline audit. For subsequent hardware changes and executed results, see [current release status](RELEASE_STATUS.md).**

Review date: 2026-09-08. Baseline: commit `dfe4364` ("unverifed design").

This project is a proposed drop-in, modern-component replacement for the Williams WPC A-12697-3 power driver board. It rectifies transformer secondaries, supplies logic and playfield power, and converts the CPU ribbon interface into 28 solenoid/flasher outputs, an 8-by-8 lamp matrix and five general-illumination triac channels. It aims to retain the original outline, mounting and harness interfaces while reducing component cost. STTNG is the principal documented integration target; the documentation's latest estimated quantity-100 parts cost is approximately $132, above the original $105–115 target. Prices were not revalidated in this review.

There is no firmware for this board. Python generates KiCad schematics, placement and manufacturing data. `tools/design_cost.py` defines circuitry, `placement_cost.py` placement, `sourcing.py` purchasing data, and `gen_project.py` / `gen_pcb.py` generate design files. `tools/spice/` contains 21 hand-written simulation decks, approximate device models and measurement checks. The routed PCB and fabrication exports are also committed. Routing/finalization relies partly on scripts from an absent sibling project and Linux-specific paths; regenerating the placed board would not reproduce the finished routing.

**Disposition: do not treat the current exports as a validated production release.** Software cannot establish 100% certainty about a future assembly. The achievable target is documented coverage of a defined operating envelope, an independently consistent release package, and successful first-article testing. Passing SPICE means the modeled circuit satisfied the selected checks; it does not establish that every relevant failure mechanism was modeled.

## Findings from the actual repository

1. **The assembly package disagrees about the +5 V feedback divider.** The schematic XML and BOM specify R264 = 11.3 kΩ and R265 = 2.1 kΩ. The PCB and both placement CSVs specify 10.5 kΩ and 2 kΩ. With the documented 0.8 V reference, these target 5.105 V and 5.000 V respectively. The SPICE decks test the former. The revision was intended to improve CPU brownout margin. Reconcile component values, MPNs, tolerances and all exports before assembly; do not let the assembler resolve the conflict.
2. **Assigned nets match, but fields drift.** Comparing both the saved and a freshly exported KiCad XML to the PCB finds 1,333 netlisted pin assignments, zero net-name mismatches, and 44 field differences: 27 values/descriptions and 17 footprint identifiers. Many are naming differences (such as a missing library prefix), not demonstrated electrical defects. Four extra PCB references are FID1–FID3 and H9. This check does not prove physical copper continuity or package pin correctness. KiCad's richer parity check also finds BR3's MPN differs: PCB `GBPC3510-E4/51`, schematic `GBPC3510W-E4/51`; review the intended lead style and heatsink arrangement.
3. **Thermal simulation and final copper assumptions disagree.** `bridge_loss` checks BR1 at 29.7 °C/W, yielding about 107 °C at 50 °C ambient. Section 10 of `THERMAL_AND_PROTECTION.md` instead describes the routed D101/D102 copper as 4.8 cm² per diode and estimates about 37 °C/W / 121 °C. That section relaxes the target from 110 to 125 °C. Reconcile the approved target and simulate the final geometry, including mutual heating; neither estimate is a measured temperature.
4. **The solenoid thermal envelope is conditional.** The existing high-power check allows the 20% duty case up to the 175 °C absolute maximum, although the design target is 125 °C. The documented additional drain copper is not implemented. Establish whether actual supported ROMs, diagnostics and faults can exceed the proposed 10% duty envelope; a replacement board cannot assume stock firmware enforces a new restriction.
5. **The saved ERC/DRC reports are errors-only.** The DRC report records zero violations and zero unconnected pads, but project rules ignore footprint-library mismatch, solder-mask bridging and several silkscreen checks. Hole-related checks are warnings. These reports are useful evidence within their configured scope, not unrestricted manufacturing approval.
6. **The original SPICE runner was not a reliable automation gate.** It returned success even when measurement checks failed, did not make simulator errors fail the overall result, and could overlook a deleted deck. The changes in this review make these cases fail, support separate output directories, record input hashes and logs, and stage portable waveform paths. Native Homebrew library/XSPICE discovery was added. Electrical decks and PCB circuitry were not changed.
7. **Documentation contains superseded assumptions.** Examples include the 5.00/5.10 V target, older bridge part names, multiple thermal targets, and connector questions marked differently across interface documents. Consolidate one revision-specific requirements table. `INTERFACE_PARITY.md` still requests physical confirmation of J126 tie-back ordering and some connector/key details. Earlier J115 questions should be reconciled with that later review, not automatically treated as unresolved wiring defects.
8. **Fresh DRC exposes drill-spacing problems.** Six pairs violate the project's 0.5 mm hole clearance. Two pairs have reported clearance 0.0000 mm: +5 V vias at (172.2, 152.8)/(172.0, 152.0), and D4 vias at (261.8, 100.2)/(261.6, 100.0), in board millimeters. Four GND pairs near (277.1, 65.2) have 0.2985 mm clearance. These are same-net pairs, not evidence of inter-net shorts, but must be repaired or explicitly accepted by the fabricator. Errors-only export hid them because hole spacing is configured as a warning.

Monte Carlo is useful after deterministic worst-case corners. Specify distributions, correlations and seeds; report failures and minimum margins, not just average behavior. Do not use a passing random sample as a substitute for bounded worst-case analysis.

The existing level-1 MOSFETs and idealized comparator/logic models are useful for function but do not establish avalanche ruggedness, common-mode behavior, partial-power behavior or layout parasitics. Start with manufacturer data and characterize uncertain models. The [ngspice documentation](https://ngspice.sourceforge.io/docs.html) describes the simulator and mixed-signal facilities. TI provides simulation resources on its [TPS54360B product page](https://www.ti.com/product/TPS54360B); check model identity and simulator compatibility before importing them. Use the [STPS20M100S datasheet](https://www.st.com/resource/en/datasheet/stps20m100s.pdf) and [IRLR3110Z product resources](https://www.infineon.com/part/IRLR3110Z) for thermal, package and stress limits.

## How MAME and PinMAME fit

Capture **raw CPU register writes**, before emulator output smoothing. A game appearing to work in an emulator says little about MOSFET temperature or physical pin mapping.

MAME's [Lua memory API](https://docs.mamedev.org/luascript/ref-mem.html) offers `install_write_tap` and `install_read_tap`. A proposed recorder should observe `:maincpu`'s `program` space, preserve event ordering and emulated timestamps, and never return replacement data from its callbacks. Record register address, byte, access mask, ROM hash, emulator version and input scenario. Install the recorder before CPU execution if boot coverage is claimed; a delayed autoboot script misses early activity. Retain the tap objects and verify they survive memory-map changes.

The current [MAME WPC DCS driver](https://github.com/mamedev/mame/blob/master/src/mame/pinball/wpc_dcs.cpp) maps writes at 0x3FE0–0x3FE3 to solenoids, 0x3FE4/5 to lamp rows/columns and 0x3FE6 to GI. Also record 0x3FFF reads/writes for the emulated zero-cross/watchdog interaction. 0x3FD4 controls the separate Fliptronic outputs: those are relevant to shared transformer loading but are not these 28 driver outputs.

Use a separately reviewed translation from register events to J113 signals: active-low ribbon data, actual strobe mapping and measured setup/hold timing. Convert that stream to logic events and piecewise-linear SPICE sources; drive several output channels and shared supplies together. Check all 256 patterns for each 8-bit register, walking-one/zero patterns, adjacent strobes, blanking during a write, and unknown initial latch state. PinMAME's [WPC implementation](https://github.com/vpinball/pinmame/blob/master/src/wpc/wpc.c) provides a second firmware-activity comparison and pinball-oriented simulation context.

Do not infer the physical ZERO CROSS waveform or BLANKING watchdog latency solely from MAME: its WPC DCS driver generates a latched zero-cross flag with a timer, and its watchdog handler is incomplete as a hardware model. Compare OEM/replacement oscilloscope captures. Emulation supplies realistic workloads; an oscilloscope/logic analyzer supplies the physical-interface oracle.

## First article and production gates

Before energizing a prototype, verify assembly polarity, custom diode anode/cathode/tab numbering, heatsink mounting, supply resistance and every connector against the approved release. Use fused, current-limited, isolated supplies and dummy loads; test the board's stored-energy discharge before handling it. This board's nominal “+50 V” supply is documented as roughly 70–75 V DC, so tests need equipment and procedures appropriate to that voltage and available fault energy.

Measure +5 V at the CPU end of the harness, including its ground return, while stepping loads. Measure gate/drain overshoot at device terminals with suitable probes. Capture GI current in both half-cycles and ZERO CROSS versus the AC waveform. Verify blanking while outputs are active; a conducting triac normally continues until current falls below holding current, so “immediately zero current” is not a valid criterion for GI. Use thermocouples and calibrated thermal imaging through thermal equilibrium, accounting for junction-to-case differences and reflective surfaces.

Only then run OEM service diagnostics and representative game scenarios in a cabinet. Repeat at the specified ambient, line and load limits. Treat an intentional fault-survival test as a separate controlled test on a sacrificial assembly where necessary. A shorted MOSFET cannot be turned off by software blanking; fuse coordination and bounded fault damage require their own evidence.

For production, require electrical bare-board testing against the released IPC-D-356 netlist, assembly inspection, and a fixture that checks every output, rail and protection function on every board. Keep serial-numbered results. Prototype success does not guarantee assembly quality for the next 100 units.

## Reproducing this review

```sh
python3 tools/verify_artifacts.py
python3 -m unittest discover -s tools -p test_verification.py
python3 tools/spice/run_all.py --output output/verification/spice
mame -listfull 'sttng*'
mame -verifyroms sttng_l7
```

The artifact command intentionally returns 1 on the current inconsistencies. Its JSON is in `output/verification/artifacts.json`. Native simulations write separate reports, logs, input SHA-256 hashes and waveform CSVs under `output/verification/spice`; the original reference results remain intact. The runner rejects missing decks, missing/out-of-range measurements and simulator stderr errors. It does not enforce newly proposed engineering limits in the table above.

For a fresh netlist, use `kicad-cli sch export netlist --format kicadxml -o output/verification/fresh-netlist.xml wpc_power_driver_cost.kicad_sch`, then pass `--netlist output/verification/fresh-netlist.xml` to the artifact checker. Run all-severity ERC and DRC using the [KiCad CLI](https://docs.kicad.org/10.0/en/cli/cli.html), with `--exit-code-violations` for automation. Refill zones on a review copy and retain its matching project rules. Merely requesting all severities does not re-enable ignored rules.

No ROMs, cabinet measurements, physical prototype or complete gameplay traces were supplied, and none of the proposed future tests should be read as already passed.

## Executed results and installed tooling

* **ngspice 47 and libngspice 47 installed with Homebrew.** All 21 decks completed with 211 passing checks and zero failing checks; source hashes still match the recorded manifest. See `output/verification/spice/RESULTS.md`. This is baseline reproduction, not completion of the proposed corner/fault campaign.
* **Five regression tests passed**, including deliberately incorrect connectivity/values, missing/out-of-range/NaN measurements, a simulator error with otherwise valid measurements, and a missing deck. `git diff --check` passed.
* **MAME 0.289 installed with Homebrew.** `-listfull 'sttng*'` recognizes STTNG variants. `-verifyroms sttng_l7` reports the ROM set missing. No firmware-derived gameplay simulation or replay was performed; that requires an available ROM set and the recorder/scenario harness described above.
* **KiCad 10.0.6 downloaded and executed**, including its bundled standard symbol/footprint libraries. The Homebrew cask could not finish because `/Library/Application Support/kicad` requires an administrator password. The downloaded application was instead run from the read-only disk image mounted at `/private/tmp/wpc-kicad`; this is temporary tooling, not a completed system installation. Native CLI: `/private/tmp/wpc-kicad/KiCad/KiCad.app/Contents/MacOS/kicad-cli`. Temporary configuration is `/private/tmp/wpc-kicad-config` (tables in its `10.0` subdirectory), with `KICAD10_SYMBOL_DIR` and `KICAD10_FOOTPRINT_DIR` pointing into the app's `Contents/SharedSupport`. Finish the normal KiCad installation locally if permanent availability is wanted.
* **Fresh XML parity:** `artifacts-fresh.json` reproduces the 1,333-pin / 44-field findings. Its expected exit status is 1 until differences are resolved.
* **Expanded DRC after zone refill and library configuration:** `drc-libraries.json` records **553 warnings, zero error-severity violations, zero unconnected items, and 255 additional schematic-parity warnings**. DRC warnings comprise 199 footprint-type, 199 library-footprint mismatch, 58 silkscreen clearance, 43 dangling track, 28 mask/silkscreen, 12 dangling via, 7 isolated copper, 6 hole-spacing, and 1 NPTH/courtyard warning. Parity warnings comprise 199 custom-field differences, 52 value/footprint/DNP differences, and 4 extra footprints. Counts are findings to triage, not 808 independent electrical defects.
* **Expanded ERC:** `erc-full.json` records **zero errors and 47 warnings**, all for embedded custom power symbols absent from the standard `power` library (+50V, +18V, +20V, +12VU). The check returned 5 as expected for violations.

DRC/ ERC used an isolated copy at `/private/tmp/wpc-board-review`; explicit `ignore` severities were promoted to warnings. Four KiCad default-ignored DRC categories remain listed in the report: missing courtyard, track endpoint centering on vias, tuning profile geometries and symbol footprint filters. Thus even this expanded run is not literally every possible check. `drc-full.json` is the earlier run before configuring the global footprint library table; prefer **`drc-libraries.json`** for final triage. The sandboxed library-enabled DRC attempt aborted without a new report; the outside-sandbox retry completed with exit 5. Fontconfig emitted a configuration diagnostic, so these runs do not validate visual exports.

The production PCB, schematics, BOM and fabrication package were not changed. Review deliverables are this report, the artifact checker, portable/failing SPICE gate, its regression tests, and separate verification outputs.
